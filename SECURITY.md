# Security and data boundaries

Project backups contain saved research data and available original PDFs, with a 63 MB portable-backup limit. Import validates notebook structure, source URL schemes, dataset hashes and attachment hashes, then opens a separate project; model settings and API keys are not restored. Import validation checks file compatibility and integrity, not scientific truth or authenticated approval. Existing analysis execution checks still require the exact fixed template and plan integrity. SVG run downloads have an additional sandboxed content security policy. Saved projects are retained when switching, and increasing revisions reject stale-tab writes.

This release is for a single person running ResearchGuide on their own computer. It binds to 127.0.0.1, rejects non-local Host headers, restricts request origins, and serves only explicitly allowed public files. Do not put it behind a public reverse proxy or treat it as an authenticated service.

Supervisor review is a local demonstration. A typed name is not an identity check. Anyone with access to the computer or data files can view or alter them. Files are not encrypted; the log is not tamper-proof. The software cannot certify research quality or permissions.

Demo mode makes no model calls. Ollama and OpenAI-compatible API modes sends saved project content to the endpoint configured by the operator. The repository excludes environment files and project data. Avoid secrets and restricted research data in artifacts, source passages, or prompts.

Before institutional deployment, the project needs authentication, authorization, secure collaboration, retention/deletion workflows, storage migrations, deployment review, and an agreed data-processing policy. Arbitrary code execution requires a separately designed sandbox and must not be added through unrestricted shell tools. The current R feature executes fixed templates only.

If GitHub private vulnerability reporting is enabled for the published repository, use that channel. Otherwise contact the maintainer through a private channel they publish. Do not post credentials, private project records, or sensitive exploit details in public issues.

API keys are saved separately in the local, unencrypted `data/model-settings.json` (or supplied through environment variables). Settings responses expose only whether a key exists. Keys are excluded from project exports, and provider error bodies are not forwarded to the browser. Existing keys are never reused after changing the endpoint or provider. Remote endpoints require HTTPS; redirects are rejected. A connection test sends only a generic prompt; guidance sends saved research context. Protect local files and consider the selected provider's data handling before sending research content.

PDF files are parsed locally using PDF.js in a worker with extraction time, heap, page, and text limits. The worker is not an operating-system sandbox. Original PDFs and extracted pages are stored in the ignored data directory. Original downloads are attachments and restricted to paper IDs in the active project. Source URLs are not fetched by the server. AI claim assessment sends selected excerpts to the configured provider; extracted full papers are not sent automatically. Exact page matching establishes text provenance only, not source authenticity or claim truth. Researcher evidence decisions are local and unauthenticated.

Consistency reviews send seven saved milestone artifacts and student explanations to the selected provider. Reports retain copies of that text in project data and exports. Quotations are matched exactly to the reviewed snapshot, which verifies provenance within the notebook, not truth or methodological correctness. Changes to the reviewed text make reports outdated; researcher responses remain local and unauthenticated.

R execution uses a pinned webR runtime in a separate process with an empty inherited environment and an unmounted in-memory R filesystem. Only validated method choices and normalized numeric CSV input reach the runner. User/model text is never evaluated as R or shell code. The process has a 30-second deadline, bounded output, a 256 MB V8 heap limit and a 512 MB limit per WebAssembly memory; this is not an OS sandbox or a total-process memory quota. webR exposes capabilities inappropriate for unrestricted untrusted code, so templates must remain fixed. CSV imports, JSON backups and reproduction downloads contain row-level data. Model planning receives column profiles, not row-level values. Guidance and consistency reviews receive aggregate execution summaries; logs and diagnostic downloads may contain sensitive results.
